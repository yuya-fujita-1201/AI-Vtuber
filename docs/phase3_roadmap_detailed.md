# AI Vtuber Phase 3 改修ロードマップ

## ビジョン: "From Personality to Partner"

**記憶と感情を持つ「デジタル・パーソナリティ」から、安定した基盤の上で、視聴者とより深く、インタラクティブに関わる「パートナー」への進化**

前回の分析と提案に基づき、Day 15からの具体的な開発タスクを以下に定義します。このロードマップは、「**基盤強化**」「**記憶と対話の深化**」「**インタラクティブ性の向上**」の3つのスプリントで構成されます。

---

## Sprint 1: 基盤強化と記憶の再構築 (Day 15 - Day 19)

このスプリントでは、アプリケーションの安定性を向上させるとともに、提案された新しいRDBベースの記憶アーキテクチャを導入します。

| Day | タスク | 詳細 |
| :--- | :--- | :--- |
| **Day 15** | **DB基盤の再設計とマイグレーション** | `rdb_memory_architecture.md`に基づき、Prismaスキーマを拡張。`CharacterTrait`, `LongTermMemory`, `TopicHistory`, `ViewerProfile`を追加し、`prisma migrate`を実行。開発用にPostgreSQLをDockerでセットアップするスクリプトも用意する。 |
| **Day 16** | **コメント処理の安定化** | 「全レス問題」を解決するため、`Agent.ts`にコメント処理用の非同期キューとスロットリング機構を実装。LLMリクエストにタイムアウトと指数バックオフによるリトライ処理を追加し、システムの堅牢性を向上させる。 |
| **Day 17** | **LLMによる意図・感情分類器の実装** | ルールベースの`CommentRouter`と`IntentClassifier`を廃止。GPT-4o-miniのJSONモードを活用した`LLMClassifierService`を新規作成し、コメントから意図・感情・トピックを構造化データとして抽出する。 |
| **Day 18** | **記憶サービスの3層構造化** | `MemoryService.ts`をリファクタリングし、短期（インメモリ/Redis）・中期（RDB）・長期（RDB+ChromaDB）の3層記憶モデルを実装。配信終了時に中期記憶を要約し、長期記憶へ統合する`consolidateStreamMemory`を実装する。 |
| **Day 19** | **キャラクター設定の導入と統合テスト** | `CharacterTrait`テーブルからAIの性格設定を読み込み、`PromptManager`を通じて動的にプロンプトへ注入する仕組みを構築。このスプリントで実装した全機能の統合テストを実施し、安定動作を確認する。 |

---

## Sprint 2: 記憶と対話の深化 (Day 20 - Day 24)

新しい記憶システムを最大限に活用し、より人間らしく、文脈を理解した対話能力を獲得することを目指します。

| Day | タスク | 詳細 |
| :--- | :--- | :--- |
| **Day 20** | **忘却曲線と記憶の鮮度管理** | 長期記憶が無限に増えることを防ぐため、`LongTermMemory`に「忘却曲線」の概念を導入。参照頻度と最終アクセス日に基づいて記憶の「鮮度スコア」を計算し、古い記憶をアーカイブするバッチ処理を実装する。 |
| **Day 21** | **話題履歴システムの活用** | `TopicHistory`テーブルを活用し、AIが「この話、前にもしましたね！」「〇〇さんはこの話題が好きですね」といったメタ的な発言をできるようにする。`PromptManager`に過去の話題履歴をコンテキストとして追加する。 |
| **Day 22** | **動的プロンプトエンジニアリング** | `EmotionEngine`が判定した現在の感情状態や、`StorytellingService`が管理する会話の雰囲気(`vibe`)に応じて、システムプロンプトの指示（例：「あなたは今、少し悲しい気持ちです」）を動的に変更するロジックを`PromptManager`に実装する。 |
| **Day 23** | **視聴者プロファイルの自動生成と活用** | 配信中の会話から視聴者の好みや特徴を推定し、`ViewerProfile`テーブルに自動で記録する機能を実装。返答生成時に「〇〇さんは猫好きでしたよね？」のように、視聴者個別の情報を自然に会話に織り交ぜる。 |
| **Day 24** | **シナリオテスト機能の強化と対話品質評価** | 特定のコメントシーケンスを再生してエージェントの挙動をテストするシナリオテスト機能を強化。複数のペルソナ（例：質問魔、荒らし、常連）に対する応答品質を評価し、プロンプトやロジックを微調整する。 |

## Sprint 3: インタラクティブ性の向上 (Day 25 - Day 29)

配信者や視聴者がAIとより直接的に関われる機能を追加し、エンターテイメント性を高めます。

| Day | タスク | 詳細 |
| :--- | :--- | :--- |
| **Day 25** | **双方向ダッシュボードの構築** | `public/dashboard.html`を大幅に機能強化。Socket.IOを使い、配信者がリアルタイムで「感情の手動オーバーライド」「独り言の強制トリガー」「NGワード設定」などを操作できるUIを実装する。 |
| **Day 26** | **外部情報連携機能（ニュース）** | 特定のキーワード（例：「今日のニュースは？」）に反応し、外部のNews APIを叩いて最新情報を取得し、それに基づいて応答を生成する機能を実装。`Agent.ts`にコマンドハンドラを追加し、`NewsApiService`を新規作成する。 |
| **Day 27** | **設定の動的リロード機能** | アプリケーションを再起動せずに、API経由で`AppConfig.ts`の一部設定（プロンプト、各種パラメータ等）を動的に再読み込みできる仕組みを実装。設定変更の反映を容易にする。 |
| **Day 28** | **単体テストの導入 (Jest)** | コードの品質と保守性を向上させるため、Jestを導入し、主要なサービスクラス（`MemoryService`, `EmotionEngine`など）に対する単体テストを作成する。`package.json`に`test`コマンドを追加し、CI連携の基礎を築く。 |
| **Day 29** | **最終統合テストとドキュメント整備** | 全ての改修項目を含めた最終的な統合テストを実施。新機能に関する`README.md`や各種ドキュメントを更新し、プロジェクトのメンテナンス性を確保する。 |
