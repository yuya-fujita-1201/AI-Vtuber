# Day 15: DB Infrastructure Redesign & Migration

## 📝 Objective

Rebuild the database infrastructure based on the new memory architecture (`docs/rdb_memory_architecture.md`). This involves extending the Prisma schema and preparing for a transition to a more robust RDB like PostgreSQL.

## 🎯 Deliverables

1.  **Updated Prisma Schema (`prisma/schema.prisma`)**
    *   Add the new models: `CharacterTrait`, `LongTermMemory`, `TopicHistory`, and `ViewerProfile`.
    *   Update existing models if necessary to establish relations.

2.  **Prisma Migration File**
    *   A new migration directory generated by the `prisma migrate dev` command, reflecting the schema changes.

3.  **PostgreSQL Setup Script (`scripts/setup-postgres.sh`)**
    *   A shell script to easily set up a PostgreSQL database using Docker for local development.
    *   This script should handle container creation, port mapping, and initial user/database setup.

4.  **Updated Environment Example (`.env.example`)**
    *   Modify the `DATABASE_URL` to reflect the new PostgreSQL connection string format.

## 🛠️ Implementation Specs

*   **Schema**: Strictly follow the schema design outlined in `docs/rdb_memory_architecture.md`.
*   **Database**: While the script sets up PostgreSQL, the Prisma schema should remain compatible with SQLite for developers who prefer a simpler setup.
*   **Migration**: Ensure the migration is non-destructive if possible, although a reset is acceptable for this major change.

## ✅ Verification

*   [ ] Running `prisma migrate dev` with the new schema completes without errors.
*   [ ] The new tables (`CharacterTrait`, `LongTermMemory`, etc.) are correctly created in the target database (either SQLite or PostgreSQL).
*   [ ] The `scripts/setup-postgres.sh` script successfully starts a functional PostgreSQL container.
*   [ ] The application can connect to the new PostgreSQL database after updating the `.env` file.
